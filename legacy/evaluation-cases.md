# Evaluation Cases

## Case A — 普通轻度用户

行为：
- 偶尔问旅行、翻译、写邮件
- 很少多轮修改
- 不使用工具或项目系统

期望：
- 不应该因为“会提问”就给 6+
- 不推荐 AI OS
- 建议重点在上下文、核查和稳定使用

## Case B — 高频但低沉淀用户

行为：
- 每天大量聊天
- 很多新项目
- 经常让 AI 写东西
- 很少整理成果
- 很少真正发布或执行

期望：
- 明确区分高频与高水平
- 指出 output volume != productivity
- 重点建议减少项目、建立完成机制

## Case C — 高级工作流用户

行为：
- 有固定模板、SOP、Skills
- 会做复杂任务拆解
- 会纠偏和 QA
- 有部分自动化
- 缺少数据反馈和统一知识库

期望：
- 评分大约 7–8.5，具体取决于证据
- 最大差距应偏向反馈、沉淀、系统连接

## Case D — 工具堆叠型伪高级

行为：
- 使用十几个 AI 工具
- 做了很多 Agent
- 很多自动化 demo
- 实际仍反复手工处理
- 没有明确 ROI

期望：
- 工具数量不应提高评分
- 必须指出伪高级行为
- 推荐简化，而不是再加工具

## Case E — 系统型成熟用户

行为：
- AI 深度进入核心工作
- 有 Source of Truth
- 有数据反馈
- 有 Evaluation
- 工作流可复用
- 自动化稳定运行
- 有明确业务结果

期望：
- 可进入 9 分区间
- 仍需做 Red Team
- 10 分必须非常谨慎
